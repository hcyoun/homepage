기능

설정 파일을 코드처럼 관리하세요

사람이 손으로 비교하던 일을 Driftwatch가 대신합니다. 빠르고, 결정적이며, 비밀값은 절대 남기지 않습니다.

📸

스냅샷

디렉터리 전체의 설정을 평탄화된 키-값으로 기록합니다. db.hosts[0]처럼 중첩 구조도 그대로 추적합니다.

🔍

정밀한 Diff

추가·삭제·변경을 파일별로 묶어 보여줍니다. 디렉터리끼리, 스냅샷끼리, 혹은 섞어서도 비교할 수 있습니다.

🔒

비밀값 자동 마스킹

password, token, api_key 같은 키는 기본으로 가려집니다. 스냅샷을 커밋해도 안전합니다.

🧩

5가지 포맷

JSON, TOML, INI, CFG, .env를 기본 지원합니다. 깨진 파일은 실패 대신 리포트에 표시합니다.

🚦

CI 친화적

check 명령은 드리프트가 있으면 종료 코드 1을 반환합니다. 파이프라인에 한 줄이면 충분합니다.

📝

리포트 3종

터미널용 컬러 텍스트, 자동화용 JSON, PR 코멘트용 Markdown 표를 --format 하나로 고릅니다.

작동 방식

세 단계면 끝

  1. 1

    기준 스냅샷 만들기

    운영 환경이 정상일 때 상태를 기록합니다.

    $ driftwatch snapshot ./prod -o baseline.json
Saved 142 keys from /srv/prod → baseline.json
  2. 2

    환경끼리 비교하기

    배포 전에 스테이징과 운영을 비교합니다.

    $ driftwatch diff ./staging baseline.json
  ~ db.pool: 10 → 50
  + feature.new_checkout: true
  3. 3

    CI에서 지키기

    기준에서 벗어나면 빌드를 멈춥니다.

    $ driftwatch check ./prod --baseline baseline.json
✖ Drift detected: 0 added, 0 removed, 1 changed
exit code 1

CI 연동

PR마다 드리프트 리포트를

GitHub Actions에 붙이면 Pull Request마다 Markdown 표로 차이를 남깁니다. 리뷰어는 설정 변경을 놓치지 않고, 운영 사고는 머지 전에 막힙니다.

  • 드리프트 시 빌드 실패 (exit 1)
  • --format markdown으로 PR 코멘트 생성
  • --ignore로 생성 파일 제외
# .github/workflows/drift.yml
name: config-drift
on: [pull_request]
jobs:
  drift:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pipx install driftwatch
      - run: |
          driftwatch check ./config \
            --baseline .driftwatch/prod.json \
            --format markdown >> $GITHUB_STEP_SUMMARY

FAQ

자주 묻는 질문

YAML은 지원하나요?

런타임 의존성 0개 원칙 때문에 기본 설치에는 포함되지 않습니다. v1.5에서 driftwatch[yaml] 선택 설치로 제공할 예정입니다.

스냅샷 파일을 Git에 커밋해도 되나요?

네. 비밀값으로 보이는 키는 기본적으로 ••••••로 저장됩니다. 원문이 꼭 필요하다면 --no-mask를 쓰되, 그 파일은 커밋하지 마세요.

Kubernetes ConfigMap이나 Terraform state도 비교할 수 있나요?

JSON으로 내보낼 수 있다면 가능합니다. 예: kubectl get cm app -o json > app.json 후 디렉터리끼리 비교하세요.

값 비교는 어떻게 이루어지나요?

모든 파일을 파일경로::키 형태로 평탄화한 뒤 키 단위로 비교합니다. 순서나 공백 차이는 드리프트로 보지 않습니다.

다음 장애는 설정 때문이 아니길.

지금 기준 스냅샷 하나만 만들어 두세요.
